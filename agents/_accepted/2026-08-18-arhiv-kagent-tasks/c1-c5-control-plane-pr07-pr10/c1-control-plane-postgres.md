## Проблема

Этап 0.2 «Persistent Project and Task Lifecycle» отмечен в roadmap как выполненный. На
самом деле весь CRUD проектов, задач и журнала аудита работает через `store.ts` —
in-memory `Map` с комментарием в первой строке: «will be replaced by PostgreSQL in v0.2+».
Всё теряется при перезапуске процесса.

Адаптер к базе написан и лежит в `services/control-plane/src/db.ts` — класс `PostgresStore`
на 172 строки со всеми нужными методами. **Он не импортируется ниоткуда.** Пул `pg`
создаётся в `main.ts` и передаётся только в маршруты аутентификации.

То есть работа наполовину сделана год назад и не подключена.

## Что сделать

### 1. Перевести маршруты на PostgresStore

- `registerRoutes` принимает пул или хранилище, как это уже сделано для `registerAuthRoutes`;
- все обработчики становятся асинхронными: методы `PostgresStore` возвращают промисы;
- `store.ts` удаляется после перевода. Оставлять два хранилища нельзя — это гарантированное
  расхождение.

### 2. Согласовать имена полей

`PostgresStore` выполняет `SELECT *` и возвращает строки как есть, то есть `project_id`,
`owner_account_id`, `created_at`, `context_refs`. Контракты и `domain.ts` используют
`projectId`, `ownerAccountId`, `createdAt`, `contextRefs`.

Сейчас это не проявляется только потому, что адаптер не используется. При подключении
внешний вид API изменится молча.

Добавить явное отображение строки базы в доменный тип в одном месте. Форма ответа API
меняться не должна: она описана в `domain.ts` и в контрактах.

### 3. Сделать /health/ready настоящей проверкой

Сейчас обработчик считает элементы в памяти. Должен проверять соединение с базой —
в `PostgresStore` для этого уже есть `healthCheck()`. При недоступности базы возвращать
503, а не 200.

### 4. Пагинация и подсчёт

`GET /v1/projects` сейчас режет массив в памяти. Использовать `offset` и `limit` адаптера,
возвращать реальный `total` из `COUNT(*)`, ограничить `limit` разумным максимумом.

### 5. Ошибки базы не отдавать наружу

Сбой запроса — это 500 с идентификатором запроса в теле и полной ошибкой в логе. Текст
ошибки PostgreSQL в ответ не попадает.

## Чего не делать

- не добавлять аутентификацию и проверку членства на `/v1/projects` и `/v1/tasks` — это
  меняет контракт API и делается отдельно;
- не менять схему таблиц и миграции;
- не трогать маршруты аутентификации: они уже работают через базу;
- не писать интеграционные тесты против настоящей базы — это задача c2.
