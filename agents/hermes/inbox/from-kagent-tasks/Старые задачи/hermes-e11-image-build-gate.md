# E11 — собирать образы на каждом прогоне

Правила — `AGENTS.md`. Ветка `wt/e11-image-build-gate` от свежего `origin/main`.

## Режим исполнения

Hermes может делегировать субагентам разбор отдельных образов. За оркестратором остаются:
структура job, решение по кешированию и прогон на совмещённой ветке.

## Проблема

Первая же попытка поднять систему целиком вскрыла **семь дефектов подряд**, и все были
давними:

| Дефект | Почему не видели |
|---|---|
| control-plane: `workspace:*` не резолвится вне workspace | образ никогда не собирался |
| исходники копировались после установки и затирали `node_modules` | то же |
| отсутствует `apps/web/public`, который требует Dockerfile | то же |
| gateway отгружал двоичную заглушку от приёма кеширования | образ собирался только вручную |
| healthcheck зовёт `wget`, которого нет в `debian-slim` | контейнер не запускали |
| gateway отвечал 500 на любой запрос без `ConnectInfo` | модульные тесты зовут middleware напрямую |

Пять из семи ловятся простой сборкой образа. Сейчас `docker compose config -q` проверяет
только синтаксис файла — он не собирает ничего.

## Что сделать

### 1. Job сборки

Отдельный job строит образы всех сервисов на каждом прогоне: gateway, control-plane,
reasoning-engine, agent-runtime, pipeline, observability, web.

Сборка — единственная цель job. Запуск контейнеров остаётся за `deployment` из E8 и `e2e`.
Разделение намеренное: сборка быстрая и падает конкретно, запуск медленный и падает
расплывчато.

### 2. Кеширование

Использовать кеш слоёв GitHub Actions, иначе прогон вырастет на минуты. Кеш не должен
скрывать поломку: изменение Dockerfile или исходников обязано приводить к пересборке.

Отдельно проверь, что ни в одном Dockerfile не осталось приёма «собрать заглушку ради кеша
зависимостей, затем скопировать настоящие исходники». Именно он отгружал пустой gateway.
Если найдёшь такой же в других образах — это находка, опиши и убери.

### 3. Доказательство

Job обязан падать на сломанном образе. Показать: временно испортить один Dockerfile,
привести красный прогон, откатить.

### 4. Реестр возможностей

Добавить возможность «образы собираются» со ссылкой на новый job как доказательство.

## Чего не делать

- не публиковать образы в реестр;
- не запускать контейнеры — это E8;
- не менять содержимое сервисов: если образ не собирается, это находка, а не помеха.

## Критерий приёмки

```bash
docker compose config -q
python scripts/drift_check.py
python -m pytest tests/unit -q
```

- job собирает все семь образов и зелёный;
- демонстрация с намеренно сломанным Dockerfile приложена;
- время прогона с кешем приведено в отчёте;
- ссылка на зелёный прогон.
