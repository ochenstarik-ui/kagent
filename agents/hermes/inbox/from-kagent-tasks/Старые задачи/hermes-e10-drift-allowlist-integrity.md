# E10 — закрыть дыру в списке известного дрейфа

Правила — `AGENTS.md`. Ветка `wt/e10-drift-allowlist-integrity` от свежего `origin/main`.

## Режим исполнения

Hermes может делегировать субагентам: распознавание точек входа pytest, распознавание
Playwright-спеков, ужесточение валидатора. За оркестратором остаются: единая модель точек
входа, чистка самого списка и прогон полного критерия на совмещённой ветке.

## Проблема

В `docs/known-drift.json` появились две записи:

```json
{ "path": "services/reasoning-engine/conftest.py",
  "follow_up_task": "None", "expires": "2026-12-31" }
{ "path": "apps/web/e2e/dashboard.spec.ts",
  "follow_up_task": "None", "expires": "2026-12-31" }
```

Обе — не дрейф. `conftest.py` подхватывается pytest автоматически, Playwright-спек
запускается своим исполнителем; оба являются точками входа, а не мёртвым кодом.

Ошибка не в том, что их внесли, а в том, что **список из инструмента давления превратился в
свалку исключений**. Договорённость была: список только сокращается, у каждой записи есть
задача, по которой она снимается. Здесь у обеих записей задача — строка `"None"`, а срок
выставлен на конец года.

Валидатор это пропускает, потому что проверяет только непустую строку:

```python
if not isinstance(entry.get("follow_up_task"), str) or not entry["follow_up_task"].strip():
```

То есть механизм, созданный ловить самообман, сам принимает заглушку.

## Что сделать

### 1. Научить проверку точкам входа

Правильное решение — не исключение, а распознавание. Так уже делали в B4 для экспортов
пакета: файл, достижимый от объявленной точки входа, дрейфом не считается.

- `conftest.py` на любом уровне — точка входа pytest;
- файлы, подходящие под шаблон тестов Playwright из его конфигурации, — точки входа своего
  исполнителя;
- источник правды о шаблонах — конфигурационные файлы, а не список путей в коде проверки.

После этого обе записи удаляются из списка, а не переписываются.

### 2. Ужесточить валидатор

- `follow_up_task` обязан выглядеть как идентификатор задачи, а не как слово-заглушка;
  строки `None`, `none`, `-`, `n/a`, `TBD` и пустые отклоняются;
- срок жизни записи ограничен сверху разумным пределом — запись на полгода вперёд не
  является временной;
- добавление записи в список требует, чтобы в теле pull request было объяснение: проверка
  сравнивает список с его версией в `origin/main` и при росте требует обоснования.

Последний пункт реализуй тем способом, который работает в вашем CI; если это невозможно
сделать надёжно — опиши почему и ограничься первыми двумя.

### 3. Тесты

- запись со строкой-заглушкой в `follow_up_task` отклоняется;
- запись со сроком за пределом допустимого отклоняется;
- `conftest.py` не попадает в вывод проверки;
- Playwright-спек не попадает в вывод проверки;
- по-настоящему недостижимый модуль по-прежнему находится — добавить временный файл,
  показать, что проверка его ловит, удалить.

## Критерий приёмки

```bash
python scripts/drift_check.py
python -m pytest tests/unit -q
```

- `docs/known-drift.json` пуст;
- проверка не сообщает ни про `conftest.py`, ни про Playwright-спеки;
- заглушка в `follow_up_task` роняет проверку — показать выводом;
- демонстрация с временным недостижимым модулем приложена;
- ссылка на зелёный прогон.

## Границы

`scripts/drift_check.py`, его конфигурация, `docs/known-drift.json`, тесты проверки.
Продуктовый код не трогать.
