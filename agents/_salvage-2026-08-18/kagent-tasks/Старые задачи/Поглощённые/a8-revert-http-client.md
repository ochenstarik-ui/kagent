## Что произошло

В ходе задачи «починить сборку gateway» исполнитель вышел за границы задания и заменил
HTTP-клиент: удалил `hyper`, `hyper-util`, `axum-extra` и добавил `reqwest` с
платформенным расщеплением TLS.

```toml
[target.'cfg(not(target_os = "windows"))'.dependencies]
reqwest = { version = "0.12.5", default-features = false, features = ["rustls-tls"] }

[target.'cfg(target_os = "windows")'.dependencies]
reqwest = { version = "0.12.5", default-features = false, features = ["native-tls"] }
```

Почему это надо убрать:

- gateway проксирует обычный HTTP на внутренние сервисы. TLS-бэкенд ему не нужен ни в
  каком виде, и вся конструкция решает проблему, созданную самим переходом на `reqwest`;
- Linux и Windows собирают **разный код**. Это уже дало расхождение: `cargo test` падал
  локально на отсутствии `dlltool.exe` из цепочки `native-tls`, при зелёном прогоне в
  непрерывной интеграции. Дефекты в такой конфигурации прячутся в обе стороны;
- зависимость добавлена без обоснования и без указания лицензии, что запрещено правилами
  репозитория;
- переписывание прокси меняет обработку заголовков, потоковую передачу и таймауты, и
  ничем не покрыто тестами.

## Что сделать

Вернуть клиент на `hyper` и `hyper-util`, как было до изменения:

1. восстановить в `Cargo.toml` зависимости `hyper`, `hyper-util`, `http-body-util`,
   `axum-extra` в тех версиях, что были в `main` (`git show origin/main:services/gateway/Cargo.toml`);
2. удалить обе секции `[target.'cfg(...)'.dependencies]` и `reqwest`;
3. вернуть проксирование на `hyper_util::client::legacy::Client` — исходную реализацию
   можно взять из `git show origin/main:services/gateway/src/main.rs`;
4. **сохранить исправления, сделанные в этой ветке**: корректный `get_request_id`,
   подключённый ограничитель частоты с вытеснением устаревших записей, форматирование,
   отсутствие предупреждений clippy, существующие тесты. Откатывается только замена
   клиента, а не вся работа;
5. пересобрать `Cargo.lock`.

Если после отката всплывёт причина, по которой `hyper` в этой ветке не работал, —
остановись и опиши её. Возможно, замена клиента была обходом реальной проблемы, и тогда
решение должно приниматься отдельно.

## Альтернатива, если владелец решит оставить reqwest

Тогда вместо отката:

- единственный бэкенд `rustls-tls` для всех платформ, никакого расщепления по `target_os`;
- обоснование в `AGENT_CHANGELOG.md` и новый ADR: почему стек проксирования сменился;
- запись о новой зависимости с лицензией в отчёте.

Какой из двух вариантов выполнять — уточни, если это не сказано в постановке.

## Критерий приёмки

```bash
cargo fmt --manifest-path services/gateway/Cargo.toml --check
cargo clippy --manifest-path services/gateway/Cargo.toml --all-targets -- -D warnings
cargo test --manifest-path services/gateway/Cargo.toml
```

Все три проходят локально, вывод приложить. После пуша дождаться прогона непрерывной
интеграции на PR #3 и приложить ссылку на прогон, где зелёные все три job: `node`, `rust`,
`python`.

Ни одна из проверок не считается пройденной по рассуждению — только по выводу.
