# Разбор закрытого PR #1 (Ветка agent/agent-workspace-cockpit)

## 1. Инвентаризация

Общий объем изменений: 52 файла, ~9180 строк (из них ~5144 строки — автоматические изменения в `pnpm-lock.yaml`). Значимый код составляет около 4000 строк.

Распределение по областям:
* **Интерфейс (apps/web):** `apps/web/app/workspaces/page.tsx`, `apps/web/app/styles.css` и файлы конфигурации. Объем: 7 файлов, ~580 строк.
* **Контракты (packages/contracts):** Определение типов `Workspace`, `Session`, `Review` (`workspace.ts`, `ids.ts`). Объем: 5 файлов, ~165 строк.
* **Control Plane (services/control-plane):** Маршруты (`workspace-routes.ts`), хранилища (`workspace-store.ts`, `postgres-workspace-repository.ts`), доменные модели (`workspace-domain.ts`). Объем: 14 файлов, ~1900 строк.
* **Инфраструктура и БД (migrations, services/gateway):** Миграции `003_agent_workspaces.sql`, `004_workspace_provisioner.sql`, интеграция в gateway. Объем: 5 файлов, ~300 строк (без учета lock-файлов).
* **Agent Runtime (services/agent-runtime):** `workspace_provisioner.py` и его тесты. Объем: 4 файла, ~500 строк.
* **Документация (docs/):** ADR и спецификации (`AGENT_WORKSPACE_COCKPIT.md`, `0004-agent-workspace-control-plane.md`, `0005-workspace-provisioner-leases.md`). Объем: 11 файлов, ~300 строк.

## 2. Классификация

**Устарело:**
* `services/control-plane/src/postgres-workspace-repository.ts` (строки 1-599) — в `main` уже осуществлен перевод control-plane на PostgreSQL, поэтому текущая реализация репозитория в ветке, вероятно, не учитывает новые абстракции и подходы работы с БД.
* Миграции `migrations/003_agent_workspaces.sql` и `migrations/004_workspace_provisioner.sql` — скорее всего потребуют переписывания под текущую структуру базы в `main`.

**Противоречит:**
* Прямое обращение в `postgres-workspace-repository.ts` может идти вразрез с принятыми недавно решениями по периметру внутренних сервисов и событиям NATS.

**Полезно и переносимо:**
* `apps/web/app/workspaces/page.tsx` (строки 1-215) и `apps/web/app/styles.css` (строки 1-323) — готовая верстка и логика компонента Cockpit (список воркспейсов, статистика сессий, управление).
* `packages/contracts/src/workspace.ts` (строки 1-134) — продуманные контракты и типы для сессий и воркспейсов.
* `services/control-plane/src/workspace-routes.ts` (строки 1-209) — HTTP маршруты (endpoints) для работы с UI и агентами (lease management, sessions, review comments).
* `services/agent-runtime/src/workspace_provisioner.py` (строки 1-194) — скрипт-провижионер для подготовки окружения.

**Полезно как идея:**
* `docs/adr/0004-agent-workspace-control-plane.md` и `docs/adr/0005-workspace-provisioner-leases.md` — зафиксированные решения по аренде (leases) и изоляции воркспейсов, которые стоит сохранить и применить при переносе кода.

## 3. Оценка переносимого

### UI: Cockpit (`apps/web/app/workspaces/page.tsx`)
* **Что дает:** Интерфейс панели управления рабочими пространствами агентов со статистикой, сессиями и лимитами.
* **Раздел ТЗ/ADR:** Закрывает требования из `AGENT_WORKSPACE_COCKPIT.md`.
* **Объем работ:** Малый. Код React-компонента почти не зависит от сложной бизнес-логики и может быть скопирован с минимальными правками путей.
* **Что помешает:** Возможные несоответствия в стилях, если в `main` поменялась дизайн-система.

### Маршруты API (`services/control-plane/src/workspace-routes.ts`) и Контракты
* **Что дает:** Набор эндпоинтов для взаимодействия Frontend -> Control Plane -> Agent Runtime.
* **Объем работ:** Средний/Высокий. Сами роуты написаны чисто, но их нужно связать с текущей актуальной реализацией PostgreSQL в `main`, внедрить проверку нового внутреннего периметра и TOTP аутентификацию (которая появилась в `main`).
* **Что помешает:** Архитектурные расхождения, отсутствие тестов интеграции с новой системой авторизации и событиями NATS.

### Runtime Provisioner (`services/agent-runtime/src/workspace_provisioner.py`)
* **Что дает:** Код изоляции и подготовки ветки для агента.
* **Объем работ:** Средний. Потребуется адаптация под текущий git-контур, реализованный в `main`.

## 4. Итоговая рекомендация

*Обоснование:* 
Открывать ветку и сливать ее целиком нельзя — слишком большой объем устаревшего кода слоя данных (репозиторий PostgreSQL, миграции) и конфликтов с новыми требованиями (TOTP, NATS, внутренний периметр). ## 5. Черновики постановок

**Задача 1: Контракты и миграции базы данных для Agent Workspaces**
* **Цель:** Перенести типы из `packages/contracts/src/workspace.ts` и адаптировать миграции (003, 004) под текущую PostgreSQL-схему в `main`.
* **Требования:** Спроектировать репозиторий для воркспейсов с учетом текущего подхода (TOTP, NATS события). Использовать идеи из ADR 004/005.

**Задача 2: Реализация API маршрутов Control Plane**
* **Цель:** Интегрировать `workspace-routes.ts` в `services/control-plane`.
* **Требования:** Обеспечить защиту эндпоинтов новым механизмом авторизации. Реализовать логику leases (аренды) с учетом событийного контура.

**Задача 3: UI Agent Workspace Cockpit**
* **Цель:** Перенести React-страницу и стили Cockpit (`apps/web/app/workspaces/page.tsx`).
* **Требования:** Подключить UI к новым контрактам API, проверить корректность работы статусов и лимитов.
