# KAgent: проектные правила

Это правило дополняет, но не заменяет `AGENTS.md` в корне KAgent. Перед работой обязательно прочитать `AGENTS.md`, `docs/KAGENT_FULL_PRODUCT_SPEC.md` и при security-изменениях `docs/THREAT_MODEL.md`.

## Контекст

- Стек: TypeScript/pnpm monorepo, Rust gateway, Python 3.12 scripts.
- Обычные каталоги: `apps/`, `packages/`, `services/`, `scripts/`, `tests/`.
- Источники истины и команды проверки брать из `AGENTS.md`; не выдумывать их по памяти.

## Контракт изменений

- TypeScript: strict, не добавлять `any`; соблюдать принятый ESM-формат импортов.
- Rust: для затронутых crate запускать `cargo fmt --check`, тесты и `cargo clippy` с проектными флагами.
- Python: 3.12, аннотации типов, ruff и проектные pytest-команды.
- Не менять существующие тесты и контракты ради совпадения с новым кодом.
- Контракты в `packages/contracts/` менять с анализом обратной совместимости.
- Пользовательские изменения отражать в требуемых проектом changelog-файлах.

## Review gate

Проверить соответствие спецификации, threat model, обратную совместимость контрактов, неизменность старых тестов и то, что новые тесты проверяют спецификацию, а не случайную реализацию.
